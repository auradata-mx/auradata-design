El select de Base UI con el estilo de AuraData: un valor largo termina en «…» sin mover la flecha, las opciones largas se leen completas en la lista, abre debajo del trigger y su borde contrasta 3:1 con la página.

## Uso

```tsx
import { Select, SelectContent, SelectItem, SelectTrigger, SelectValue } from '@/components/ui/select';

const PERIODS = [
  { value: 'month', label: 'Este mes' },
  { value: 'year', label: 'Este año' },
];

<Select items={PERIODS} defaultValue="month">
  <SelectTrigger aria-label="Periodo">
    <SelectValue />
  </SelectTrigger>
  <SelectContent>
    {PERIODS.map((period) => (
      <SelectItem key={period.value} value={period.value}>
        {period.label}
      </SelectItem>
    ))}
  </SelectContent>
</Select>;
```

Pasa `items` al `Select`: así el trigger muestra la etiqueta del valor («Este mes») y no su clave (`month`).

## Cuándo usarlo

- **Un valor de una lista corta** que se conoce de antemano.
- **En formularios**, con `react-hook-form`: el `Select` no es un input nativo, así que va con `Controller` (`value` y `onValueChange`) y el `ref` en el `SelectTrigger`, para que el foco llegue al primer error.

## Cuándo no

- **Varios valores o una lista larga que hay que buscar**: `Combobox` (con `multiple`, cada valor es un chip).
- **En el teléfono**, donde el selector del sistema es lo mejor: `NativeSelect`.
- **Cambiar entre pocas vistas visibles a la vez** (Tabla | Gráfica): `Tabs` o `ToggleGroup`.
