| Parte | Regla |
| --- | --- |
| Estructura | `FieldGroup` con un `Field` por campo; `FieldSet` y `FieldLegend` para agrupar |
| Etiqueta | Siempre visible, con `FieldLabel` y `htmlFor`. El placeholder es un ejemplo, nunca la etiqueta |
| Ayuda | `FieldDescription` debajo, en una línea: para qué sirve el campo |
| Error | `aria-invalid` en el control, `data-invalid` en el `Field` y `FieldError` con cómo corregirlo |
| Botones | Al final, la acción principal primero, con verbo: «Guardar cambios», no «Aceptar» |

### Cuándo validar

| Momento | Qué validar |
| --- | --- |
| Al escribir | Nada. No marques un error mientras la persona aún escribe |
| Al salir del campo | El formato: un correo, un número, una fecha |
| Al enviar | Todo. Lleva el foco al primer campo con error |
| Después del servidor | Lo que solo el servidor sabe («Ya existe un informe con ese nombre») en el campo; lo demás, en un `Alert` arriba del formulario |

### Los mensajes de error

Qué está mal y cómo arreglarlo, sin culpas (ver [Voz](?path=/docs/brand-05-voz--docs)).

| Sí | No |
| --- | --- |
| {'Escribe un correo completo, como ana@empresa.mx.'} | Correo inválido |
| El nombre ya existe. Prueba con otro. | ¡Error! Nombre duplicado |
| Elige una fecha anterior al 21 nov 2026. | Fecha fuera de rango |

### Al enviar

El botón principal muestra un spinner y «Guardando…», queda deshabilitado con `aria-busy` y los campos siguen visibles. Al terminar, un toast confirma («Cambios guardados»); si falla, el error queda en el formulario, no en un toast que se va. Ver [Estados](?path=/docs/brand-09-estados-y-accesibilidad--docs).

### Qué control usar

| Dato | Control |
| --- | --- |
| Texto corto | `Input`: el de siempre |
| Varios valores de una lista | `Combobox` con `multiple`: busca, y cada valor es un chip que se quita |
| Etiquetas libres | `Combobox` con `multiple` y una opción «Crear «…»» (Components/Combobox/Tags) |
| Un número con pasos | `NumberInput`: − y +, y las flechas del teclado |
| Dinero | `CurrencyInput`: agrupa los miles al escribir (1,284,500.50) |
| Teléfono | `PhoneInput`: 10 dígitos con lada; acepta +52 |
| Un día | `DatePicker`: el calendario en español (21 nov 2026) |
| Una hora | `TimePicker`: 24 horas, cada 30 minutos (14:30) |
| Día y hora | `DateTimePicker`: un solo valor para los dos |
| Contraseña nueva | `PasswordInput` y `PasswordStrength`: mostrarla, y qué le falta para ser segura |
| Código de verificación | `InputOTP`: seis casillas; el teléfono ofrece el código del SMS |
| Un archivo para importar | `FileDropzone` y `CsvPreview`: arrastrar o elegir, y ver las primeras filas |
| Un formulario largo | `Stepper`: pocos campos por paso, y dónde vas |

### Formularios con validación

Los formularios se validan con [react-hook-form](https://react-hook-form.com) y un esquema de [zod](https://zod.dev) sobre nuestros `Field`. El esquema dice qué es válido y escribe los mensajes, en la voz de la marca:

```tsx
const schema = z.object({
  name: z.string().trim().min(1, "Escribe un nombre para la conexión."),
  port: z.number({ error: "Escribe el puerto, como 5432." }).min(1).max(65535, "El puerto va de 1 a 65535."),
})

const form = useForm({ resolver: zodResolver(schema), defaultValues, mode: "onTouched" })

<Controller
  name="name"
  control={form.control}
  render={({ field, fieldState }) => (
    <Field data-invalid={fieldState.invalid || undefined}>
      <FieldLabel htmlFor="name">Nombre</FieldLabel>
      <Input {...field} id="name" aria-invalid={fieldState.invalid || undefined} />
      {fieldState.error && <FieldError>{fieldState.error.message}</FieldError>}
    </Field>
  )}
/>
```

| Regla | Cómo |
| --- | --- |
| Valida al salir del campo y al enviar | `mode: "onTouched"`: nada mientras escribe; un error ya visible se va en cuanto se corrige |
| El foco va al primer error | Al enviar, react-hook-form enfoca el primer campo con error: pásale su `ref` a cada control (`ref` en `SelectTrigger` y `Switch`, `inputRef` en `NumberInput`) |
| Los controles de Base UI van con `Controller` | `Select`, `NumberInput`, `Switch` y los selectores de fecha no son inputs nativos: `value` y `onValueChange` en lugar de `register` |
| Los errores del servidor | En su campo con `setError("name", …)`; los que no son de un campo, con `setError("root.server", …)` en un `Alert` arriba |
| Mientras guarda | El botón con `loading` y «Guardando…» (`formState.isSubmitting`) |

El bloque «Nueva conexión» (`connection-form`) junta todo: el esquema, los controles de Base UI y los errores del servidor. Prueba enviarlo vacío.

## Un informe de AuraData BI

De arriba abajo, siempre en este orden:

| Bloque | Componente | Qué lleva |
| --- | --- | --- |
| Encabezado | `PageHeader` | El título y, a la derecha, el periodo y las acciones |
| Filtros | `DateRangeFilter`, `FacetedFilter`, `RangeFilter`, `FilterChips` | El periodo primero; luego los segmentos (región, producto) y los rangos (monto); los chips debajo dicen qué está filtrado |
| KPI | `KpiCard` | De 3 a 4, con su cambio contra el periodo anterior |
| Gráficas | `Chart` | La tendencia primero, luego las comparaciones |
| Detalle | `DataTable` | Búsqueda, filtros por columna, orden y columnas |

<div className="sb-unstyled my-6 grid gap-6 rounded-2xl border p-6">
  <PageHeader
    title="Ventas 2026"
    description="Actualizado hace 5 minutos."
    actions={
      <>
        <DateRangeFilter today={TODAY} defaultValue={presetRange('this-month', TODAY)} />
        <Button>Compartir</Button>
      </>
    }
  />
  <div className="grid gap-4 lg:grid-cols-3">
    <KpiCard label="Ventas del mes" value="$4.16 M" change={0.062} comparison="vs. octubre" />
    <KpiCard label="Clientes activos" value="1,284" change={-0.021} comparison="vs. octubre" />
    <KpiCard label="Costo de envío" value="$182,400" change={0.04} goodDirection="down" comparison="vs. octubre" />
  </div>
</div>

| Regla | Por qué |
| --- | --- |
| Los filtros arriba de todo lo que filtran | Quien lee sabe de qué periodo son los números antes de verlos |
| El periodo siempre visible | «1 nov 2026 – 21 nov 2026» en el botón, no solo «Este mes» al abrirlo |
| Lo filtrado, a la vista | Un chip por filtro con su «×» y «Limpiar todo»; cada filtro cuenta lo que dejan los demás. Las condiciones Y/O van en `FilterBuilder` |
| Un KPI, una comparación | «vs. octubre» dice contra qué se mide el cambio |
| Estados por bloque | Cada gráfica carga, falla o queda vacía sola: un `ErrorState` no tumba la página |

## Patrones de app

Las piezas que se repiten en la navegación de AuraData BI. Úsalas antes de armar una propia.

| Componente | Para qué y cómo |
| --- | --- |
| `TabsCount` | Secciones de una página con su conteo. El número es parte del nombre de la pestaña («Míos 12»); más de `max` se lee «99+» |
| `MasterDetail` | Una lista y su detalle. En el teléfono el detalle reemplaza a la lista; «Volver» regresa a la fila que lo abrió |
| `OnboardingChecklist` | Los primeros pasos. El siguiente lleva el botón principal; la guía se puede ocultar |
| `Tour` | Presentar una pantalla nueva en tres a cinco pasos, cada uno en un elemento visible. Siempre se puede saltar y no vuelve a abrirse solo |
| `ShortcutsDialog` | Los atajos. Se abre con «?» fuera de los campos de texto; las teclas van en `Kbd` |
| `UserMenu` | La cuenta: espacio, tema, idioma, ayuda y «Cerrar sesión» al final |
| `EmptyIllustration` | Nada que mostrar, dentro de `Empty`: qué falta y el primer paso. La ilustración es decorativa |
