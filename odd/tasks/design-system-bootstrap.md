# AuraData design system

Objective: one private repo with the AuraData brand (tokens), a shadcn registry on Base UI and a Storybook catalog, adopted by every AuraData product.
Branch: main, then one branch per phase. Delivery: ask-on-risk. Test runner: vitest (tokens), `shadcn build` and `tsc -b` (registry), `storybook build`.

## Specs

- S1: A repo outside Superset, `/Volumes/Data/programming/personal/auradata-design`, a sibling of `superset/` and `auradata-mx/`.
- S2: `@auradata/tokens`: one source of the brand (colors light and dark, fonts, radii, shadows, motion, chart palette) built with Style Dictionary into CSS variables, a Tailwind 4 `@theme`, shadcn semantic variables, Infima (Docusaurus) variables and an antd theme. Values match the current `THEME_DEFAULT`/`THEME_DARK` of `superset/auradata_config.py` and the `@theme` of `auradata-mx/src/styles/global.css`.
- S3: A shadcn registry with the latest stack: shadcn CLI v4 with `--base base` (Base UI), Tailwind 4, themed by `@auradata/tokens`, served from a private GitHub repo ("Private GitHub Registries", shadcn changelog Aug 2026).
- S4: Storybook as the workshop and catalog of the registry components.
- S5: UI SDK (vercel-labs/ui) stays out while it is in beta.
- S6 (user, 2026-11-20): "hay que hacer un plan completito de todo lo que tenemos que hacer": the plan below covers publishing, completing the tokens, adopting them in each product, growing the registry, quality and brand docs.
- S8 (user, 2026-11-21): "Ahorita lo probé y no funcionó, la verdad. Y no sé por qué estás utilizando un alert. No es posible hacer como una pantalla de login o algo así porque no se ve de la mejor manera." Then "Nuestro login con la marca (Recommended)": the published Storybook gets a branded sign-in page (our components, light and dark) instead of the browser's basic-auth dialog; one team password kept in Coolify; a signed, HttpOnly session cookie; nothing reachable without it except the sign-in page and its assets.
- S7 (user, 2026-11-21): "Pues vamos a agregar y arreglar todo lo que me dices por favor", about the proposal: status components (Alert and Badge in success, warning, info), number and date formatting (es-MX), data table, date range filter with presets, ⌘K search, workspace switcher and light/dark toggle, error and 404 states, an ECharts theme in the tokens, marketing blocks (hero, CTA band, benefits grid, FAQ, footer) with eyebrow, gradient heading and aura background, the faint dark switch, a KPI sparkline, and AI Elements for chat. Only what shadcn lacks or AuraData changes is published; each new component has a story and passes the story, a11y and visual checks.

- S10 (user, 2026-11-21): "le des una revisada súper general para que cheques que todo funcione de una manera perfecta en móvil, en web, en todo. Estos componentes no deben de tener, pues como tal fallos, deben de ser muy buenos … detallitos muy pequeños son los que quiero que cheques este márgenes, paddings, alineaciones … esos detalles pequeños son los que hacen que unos componentes sientan premium". Every story and docs page is checked at 390px and 1280px, light and dark; spacing, alignment, overflow, tap targets and copy defects are fixed in the components (or the stories when the defect is only the demo).
